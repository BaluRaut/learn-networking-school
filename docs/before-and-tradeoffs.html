⏮️ Before & trade-offs

Every tool replaced something worse — and is itself the wrong tool somewhere. For each big idea: what life was like before, honest merits ✅ / demerits ❌, and where to use it 👍 vs not 👎.

📬 TCP vs UDP — lesson 05

⏮️ Before both (1970s ARPANET)

One protocol tried to do everything; the split into IP (delivery) and TCP/UDP (contracts) is what let the internet grow.

✅ Merits

  • TCP: complete, ordered, retransmitted — you never think about loss
  • UDP: no handshake, no buffers, tiny headers — the fastest thing possible

❌ Demerits

  • TCP: a round trip to start, head-of-line blocking, buffers
  • UDP: you handle loss, order and congestion yourself

👍 Use when

  • TCP for anything that must be complete: web, mail, databases
  • UDP for DNS, video, voice, games — and QUIC/HTTP/3

👎 Think twice when

  • UDP for a file transfer you wrote yourself
  • TCP for 20 ms voice packets

🏫 IPv4 vs IPv6 — lesson 02

⏮️ Before IPv6 (1998)

Four billion addresses looked infinite in 1981; NAT was invented to stretch them, and every home got the same 192.168.0.x.

✅ Merits

  • IPv6: 340 undecillion addresses, no NAT needed, every device reachable
  • IPv4: everything supports it, every engineer knows it

❌ Demerits

  • IPv6: two stacks to run, longer addresses to read, some networks still lack it
  • IPv4: scarce, expensive, NAT everywhere

👍 Use when

  • dual-stack by default; IPv6 first on mobile and in new clouds
  • IPv4 for anything that must work everywhere today

👎 Think twice when

  • IPv6-only for a public service in 2026
  • IPv4-only for a new mobile app backend

📖 Public vs private DNS — lesson 06

⏮️ Before DNS (hosts.txt, 1983)

Every computer downloaded one text file of every name on the network. It stopped scaling at a few hundred hosts.

✅ Merits

  • public DNS (Route 53, Cloudflare): reachable by everyone, anycast, fast
  • private zones: internal names (db.internal) that never leak

❌ Demerits

  • public: a typo is global in one TTL
  • private: split-horizon confusion — the same name meaning two things

👍 Use when

  • public for anything users type
  • private for service discovery inside a VPC or cluster

👎 Think twice when

  • internal database names in public DNS
  • a public site only in a private zone

🔒 TLS 1.3 vs 1.2 — lesson 08

⏮️ Before TLS (SSL, 1995)

HTTP sent passwords in the clear; SSL bolted encryption on, then accumulated twenty years of broken ciphers.

✅ Merits

  • 1.3: one round trip, only strong ciphers, forward secrecy by default
  • 1.2: supported by ancient clients and appliances

❌ Demerits

  • 1.3: some middleboxes still choke on it
  • 1.2: allows weak configurations if you let it

👍 Use when

  • 1.3 everywhere; keep 1.2 only for known old clients
  • never anything older

👎 Think twice when

  • TLS 1.0/1.1 or SSL for anything
  • disabling TLS 'for speed' inside a network

🚪 NAT vs public addresses — lessons 02, 10

⏮️ Before NAT (~1994)

Every machine had a public address and was reachable from the whole internet — fine for 1,000 universities, fatal for a billion phones.

✅ Merits

  • NAT: one public address serves a building; nothing inside is reachable unless you say so
  • public addresses: simple, no port mapping, peer-to-peer just works

❌ Demerits

  • NAT: inbound needs port forwarding; carrier-grade NAT breaks some apps
  • public: every device is a target; addresses are scarce

👍 Use when

  • NAT for homes, offices, private subnets in the cloud
  • public addresses for servers that must be reached

👎 Think twice when

  • a database with a public address
  • expecting inbound connections to a phone behind carrier NAT

🏪 L4 vs L7 load balancing — lesson 11

⏮️ Before load balancers (DNS round-robin)

One name pointed at three addresses and hoped; a dead server still got a third of the visitors until its TTL expired.

✅ Merits

  • L4: fast, protocol-agnostic, keeps TLS end-to-end
  • L7: routes by URL and header, terminates TLS, retries, can rewrite

❌ Demerits

  • L4: cannot see the request, so cannot route by path
  • L7: more CPU, it must understand HTTP

👍 Use when

  • L4 for databases, gRPC passthrough, raw TCP
  • L7 for web apps, APIs, canary routing

👎 Think twice when

  • L7 for a Postgres connection
  • L4 when you need per-path routing

🕳️ VPN vs zero trust — lesson 10

⏮️ Before VPNs

Working from outside the building meant a modem into the office; the network's edge WAS the security.

✅ Merits

  • VPN: one tunnel, you are inside; simple mental model
  • zero trust: every request authenticated; no 'inside'

❌ Demerits

  • VPN: inside = trusted, so one stolen laptop sees everything
  • zero trust: every service needs identity-aware access (mTLS, SSO)

👍 Use when

  • VPN for small teams and legacy systems
  • zero trust for anything public-facing or large

👎 Think twice when

  • a flat VPN as the only control for a hundred services
  • zero trust theatre: a login page in front of an open database
