⏮️ आधी काय होते & फायदे-तोटे

प्रत्येक साधनाने काहीतरी वाईट गोष्ट बदलली — आणि तेच साधन कुठेतरी चुकीचे ठरते. प्रत्येक मोठ्या कल्पनेसाठी: आधी जीवन कसे होते, प्रामाणिक फायदे ✅ / तोटे ❌, आणि कुठे वापरावी 👍 विरुद्ध कुठे नाही 👎.

📬 TCP विरुद्ध UDP — धडा 05

⏮️ दोन्हींच्या आधी (1970 चे ARPANET)

एकाच protocol ने सगळे करायचा प्रयत्न केला; IP (पोहोच) आणि TCP/UDP (करार) यांची फूट यामुळेच internet वाढू शकले.

✅ फायदे

  • TCP: पूर्ण, क्रमाने, पुन्हा पाठवलेले — हरवण्याचा विचारच नाही
  • UDP: handshake नाही, buffers नाहीत, छोटे headers — शक्य तितके वेगवान

❌ तोटे

  • TCP: सुरू करायला एक फेरी, head-of-line blocking, buffers
  • UDP: हरवणे, क्रम आणि गर्दी तुम्हीच सांभाळता

👍 वापरा जेव्हा

  • पूर्ण असायलाच हवे त्या सगळ्यासाठी TCP: web, mail, databases
  • DNS, video, आवाज, खेळ — आणि QUIC/HTTP/3 साठी UDP

👎 दोनदा विचार करा जेव्हा

  • तुम्ही स्वतः लिहिलेल्या file transfer साठी UDP
  • 20 ms च्या आवाज packets साठी TCP

🏫 IPv4 विरुद्ध IPv6 — धडा 02

⏮️ IPv6 आधी (1998)

1981 मध्ये चार अब्ज पत्ते अनंत वाटले; ते ताणायला NAT शोधले गेले, आणि प्रत्येक घराला तेच 192.168.0.x मिळाले.

✅ फायदे

  • IPv6: 340 undecillion पत्ते, NAT ची गरज नाही, प्रत्येक device गाठता येते
  • IPv4: सगळे त्याला साथ देतात, प्रत्येक अभियंत्याला माहीत

❌ तोटे

  • IPv6: दोन stacks चालवायचे, लांब पत्ते वाचायचे, काही networks मध्ये अजून नाही
  • IPv4: दुर्मिळ, महाग, सगळीकडे NAT

👍 वापरा जेव्हा

  • default dual-stack; mobile आणि नव्या clouds मध्ये आधी IPv6
  • आज सगळीकडे चालायलाच हवे त्यासाठी IPv4

👎 दोनदा विचार करा जेव्हा

  • 2026 मध्ये सार्वजनिक service साठी फक्त IPv6
  • नव्या mobile ॲप backend साठी फक्त IPv4

📖 सार्वजनिक विरुद्ध खाजगी DNS — धडा 06

⏮️ DNS आधी (hosts.txt, 1983)

प्रत्येक संगणक network वरच्या प्रत्येक नावाची एक मजकूर-फाइल download करायचा. काही शे hosts वर ते थांबले.

✅ फायदे

  • सार्वजनिक DNS (Route 53, Cloudflare): सगळ्यांना गाठता येणारे, anycast, वेगवान
  • खाजगी zones: कधीच न गळणारी अंतर्गत नावे (db.internal)

❌ तोटे

  • सार्वजनिक: एक चूक एका TTL मध्ये जागतिक
  • खाजगी: split-horizon गोंधळ — एकाच नावाचे दोन अर्थ

👍 वापरा जेव्हा

  • वापरकर्ते टाइप करतात त्या सगळ्यासाठी सार्वजनिक
  • VPC किंवा cluster आतल्या service discovery साठी खाजगी

👎 दोनदा विचार करा जेव्हा

  • सार्वजनिक DNS मध्ये अंतर्गत database ची नावे
  • सार्वजनिक साइट फक्त खाजगी zone मध्ये

🔒 TLS 1.3 विरुद्ध 1.2 — धडा 08

⏮️ TLS आधी (SSL, 1995)

HTTP passwords उघड पाठवायचे; SSL ने encryption जोडले, मग वीस वर्षे मोडक्या ciphers साठवल्या.

✅ फायदे

  • 1.3: एक फेरी, फक्त बळकट ciphers, default forward secrecy
  • 1.2: जुनाट clients आणि उपकरणे साथ देतात

❌ तोटे

  • 1.3: काही middleboxes अजून अडखळतात
  • 1.2: दिले तर कमकुवत configuration चालवते

👍 वापरा जेव्हा

  • सगळीकडे 1.3; 1.2 फक्त माहीत असलेल्या जुन्या clients साठी
  • त्याहून जुने कधीच नाही

👎 दोनदा विचार करा जेव्हा

  • कशासाठीही TLS 1.0/1.1 किंवा SSL
  • network च्या आत 'वेगासाठी' TLS बंद करणे

🚪 NAT विरुद्ध सार्वजनिक पत्ते — धडे 02, 10

⏮️ NAT आधी (~1994)

प्रत्येक मशीनला सार्वजनिक पत्ता होता आणि अख्ख्या internet वरून गाठता यायचे — 1,000 विद्यापीठांसाठी ठीक, अब्जावधी फोनसाठी घातक.

✅ फायदे

  • NAT: एक सार्वजनिक पत्ता अख्खी इमारत सांभाळतो; तुम्ही म्हणाल तरच आतले काही गाठता येते
  • सार्वजनिक पत्ते: साधे, port mapping नाही, peer-to-peer सहज चालते

❌ तोटे

  • NAT: आत येणाऱ्याला port forwarding लागते; carrier-grade NAT काही ॲप्स मोडते
  • सार्वजनिक: प्रत्येक device लक्ष्य; पत्ते दुर्मिळ

👍 वापरा जेव्हा

  • घरे, ऑफिसे, cloud मधल्या खाजगी subnets साठी NAT
  • गाठता यायलाच हवेत त्या servers साठी सार्वजनिक पत्ते

👎 दोनदा विचार करा जेव्हा

  • सार्वजनिक पत्ता असलेला database
  • carrier NAT मागच्या फोनला आत येणाऱ्या जोडण्यांची अपेक्षा

🏪 L4 विरुद्ध L7 load balancing — धडा 11

⏮️ Load balancers आधी (DNS round-robin)

एक नाव तीन पत्त्यांकडे दाखवायचे आणि आशा करायचे; मेलेल्या server ला TTL संपेपर्यंत तिसरा हिस्सा पाहुणे मिळायचे.

✅ फायदे

  • L4: वेगवान, protocol-निरपेक्ष, TLS टोकापासून टोकापर्यंत ठेवते
  • L7: URL आणि header नुसार route, TLS संपवते, पुन्हा-प्रयत्न, पुन्हा लिहू शकते

❌ तोटे

  • L4: विनंती दिसत नाही, म्हणून path नुसार route नाही
  • L7: जास्त CPU, HTTP समजावेच लागते

👍 वापरा जेव्हा

  • databases, gRPC passthrough, कच्च्या TCP साठी L4
  • web ॲप्स, API, canary routing साठी L7

👎 दोनदा विचार करा जेव्हा

  • Postgres जोडणीसाठी L7
  • path नुसार routing हवे असताना L4

🕳️ VPN विरुद्ध zero trust — धडा 10

⏮️ VPN आधी

इमारतीबाहेरून काम म्हणजे ऑफिसमध्ये modem; network ची सीमा हीच सुरक्षा होती.

✅ फायदे

  • VPN: एक बोगदा, तुम्ही आत; साधे मानसिक चित्र
  • zero trust: प्रत्येक विनंती authenticated; 'आत' असे काही नाही

❌ तोटे

  • VPN: आत = विश्वासार्ह, म्हणून एक चोरलेला लॅपटॉप सगळे पाहतो
  • zero trust: प्रत्येक service ला ओळख-जाणणारा प्रवेश लागतो (mTLS, SSO)

👍 वापरा जेव्हा

  • छोट्या टीम्स आणि जुन्या प्रणालींसाठी VPN
  • सार्वजनिक किंवा मोठ्या कशासाठीही zero trust

👎 दोनदा विचार करा जेव्हा

  • शंभर services साठी एकमेव नियंत्रण म्हणून सपाट VPN
  • zero trust चे नाटक: उघड्या database समोर login पान
